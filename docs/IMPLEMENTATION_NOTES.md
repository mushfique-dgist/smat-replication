# Implementation notes

This document records every detail of the implementation that the SMAT papers [1, 2] do not specify, or that required a decision when building on MyoAssist commit `3b945c7` [3], together with the choice made and, where measured, the supporting evidence. The identifiers (D-...) are referenced from the source code.

Sources of the reproduced settings: Algorithm S1 (curriculum), Table S2 (outer reward weights), Table S3 (per-joint imitation weights) and Table S4 (PPO hyperparameters) of the supplementary material of [2]; the network sizes and the stage descriptions of [1].

## 1. Software environment

**D-DEPS-01. Package versions.** MyoAssist's `requirements.txt` leaves stable-baselines3 unpinned. Version 2.7.1 (released 2025-12-05) is used, the newest release before the SMAT preprint (2026-03-08); 2.8.0 followed on 2026-04-01. CPU-only PyTorch 2.14.1 is installed from the PyTorch CPU index. MyoAssist's own pins give mujoco 3.3.3, gymnasium 0.29.1 and numpy 2.2.6. `deploy/setup_smat3.sh` asserts all five versions.

**D-DEPS-02. Test runner.** pytest 9.1.1. It does not take part in training.

**D-ENV-01. Environment construction.** `deploy/setup_smat3.sh` builds the environment with uv. An equivalent environment built with `python3.12 -m venv` gives the same package set (`smat_r3/pip_freeze.txt`).

**D-PHYS-01. Simulation rates.** Control at 50 Hz (Δt = 0.02 s, as stated in [1]) and physics at 1200 Hz, MyoAssist's configuration default, giving a frame skip of 24.

## 2. Device model

**D-XML-01. Device bodies.** The papers report the hardware device mass (5.94 kg) and its motor (25 N·m peak) but not its geometry or mass distribution. The model (`smat_r3/models/smat_hipexo_26.xml`, generated by `build_hipexo_xml.py` from MyoAssist's `myoLeg26_BASELINE.xml`) adds a 2.5 kg pelvis unit and two 1.72 kg hip units (5.94 kg in total). The units are fused rigidly to their parent bodies (no joints) and excluded from collisions; MuJoCo derives their inertia from the primitive shapes. Positions and shapes are assumptions.

**D-XML-02. Actuators.** Two general actuators, `Exo_R` and `Exo_L`, act directly on the existing `hip_flexion_r` and `hip_flexion_l` joints, following the pattern of MyoAssist's stock ankle-device models. Their gain is set at run time to the stage torque cap (0 / 0 / 6 / 25 N·m).

**D-XML-03. Command range.** The command range is [−1, 1], so the device can assist both hip flexion and extension. MyoAssist's stock ankle devices use [−1, 0] (plantarflexion only). This is an assumption.

**D-XML-04. File locations.** The generated model lives outside MyoAssist's tree. Its mesh directory and include path therefore point into `ext/myoassist_3b945c7/models/`. MyoAssist 3b945c7 references `l_radius.stl` and `l_ulna.stl`, while the files are named `l_radius.STL` and `l_ulna.STL`; two symbolic links created by the setup script resolve both names on case-sensitive filesystems.

**D-XML-05. Torque scaling.** Each actuator has gear 1 and gain equal to the stage torque cap, so the applied torque is the cap times the command. This is equivalent to "gear = stage torque cap" and is checked by `tests/test_policy.py`.

**D-XML-06. Stage-1 model.** Algorithm S1 adds the device mass at Stage 2. Stage 1 therefore uses `smat_hipexo_26_stage1.xml` (generated by `build_stage1_xml.py`): the device model without the three device bodies, with the same joints, actuators and observation. It is 5.94 kg lighter than the device model.

## 3. Reference motion

The imitation reference is MyoAssist's `rl_train/reference_data/short_reference_gait.npz` (44,900 samples at 500 Hz), resampled to the control rate as MyoAssist does.

**D-REF-01. Gait-cycle length.** The file carries no cycle length. Autocorrelation of the right hip flexion angle gives 553 samples (1.106 s). This estimate is used only by the diagnostics.

**D-REF-02. Matched degrees of freedom.** 18 of the 37 reference DOFs match model joint names: the 6 pelvis DOFs and the 12 leg DOFs of Table S3. The others are upper-body DOFs, absent from the model.

**D-REF-03. Sign convention.** The model defines the hip adduction and hip rotation axes identically on both legs, so left-side values require a sign flip. `pelvis_tz`, `hip_adduction_l` and `hip_rotation_l` are multiplied by −1. With the flip, the correlation between the right foot's lateral position and the left foot's half-cycle-shifted lateral position is −0.789; without it, −0.316. The flip gives the expected mirror pattern. Diagnostics: `eval/check_reference_fit.py`, `eval/check_vertical_axis.py`, `eval/check_noflip_control.py`.

**D-REF-04, D-REF-07. Joint-range mismatch.** The reference requires more hip extension than the model's joint range allows. Measured on the resampled series (4,490 samples):

| DOF | model range (rad) | samples beyond range | reference min / max (rad) |
|---|---|---|---|
| hip_flexion_r | [−0.349, 2.356] | 21.67 % | −0.516 / 0.399 |
| hip_flexion_l | [−0.349, 2.356] | 17.51 % | −0.474 / 0.401 |
| ankle_angle_l | [−1.134, 0.349] | 3.92 % | −0.445 / 0.394 |
| knee_angle_r | [−2.531, 0.0] | 0.51 % | −1.102 / 0.012 |
| ankle_angle_r | [−1.134, 0.349] | 0.11 % | −0.505 / 0.360 |

The remaining tracked DOFs stay within range. Each tracked DOF is clamped to the model's joint range before the reference is used. The `mtp_angle` series are constant zero in this trial.

**D-REF-05. Foot height.** With the reference pose applied to the model, the foot lies below the floor in 85.23 % of frames: median depth 1.84 cm, 90th percentile 6.86 cm, 99th percentile 7.89 cm, maximum 8.39 cm. MyoAssist applies no height correction, and none is applied here; the reference is used as SMAT used it. The file's `data_length` metadata (449,000) disagrees with its array length (44,900); the array length is used. Diagnostic: `eval/check_full_reference_fit.py`.

**D-REF-06. Reference state initialisation.** At every reset all 18 matched DOFs are set from a randomly chosen reference frame, independently of which subset the stage's imitation reward tracks.

## 4. Observations and actions

**D-OBS-01. Human observation.** [1] describes the human observation only as the musculoskeletal body state, and MyoAssist 3b945c7 ships no configuration for the 26-muscle model. The observation uses MyoAssist's observation mechanism with these keys:

- 16 joint angles: pelvis_ty, pelvis_tilt, pelvis_list, pelvis_rotation, and hip flexion, hip adduction, hip rotation, knee, ankle and mtp of both legs;
- 18 joint velocities: the same DOFs plus pelvis_tx and pelvis_tz;
- 26 muscle activations;
- 4 foot sensors;
- the target speed.

That makes 65 dimensions. In Stage 4 the human actor also receives the exoskeleton's 2-dim command of the same control step (D-OBS-03), for 67.

**D-OBS-02, D-OBS-04. Exoskeleton observation.** [1] and [2] specify a 3-step history of bilateral hip angle and velocity (12 dimensions) and of the exoskeleton's own normalised torque command (6 dimensions), without an ordering or initial padding. Layout:

1. `[hip_flexion_r, hip_flexion_l, hip_flexion_vel_r, hip_flexion_vel_l]` for t−2, t−1, t;
2. then `[u_r, u_l]` for t−2, t−1, t, where u is the command in [−1, 1].

Missing history at the start of an episode is filled with zeros.

**D-OBS-03. Stage-4 human input.** The two extra Stage-4 inputs are assembled inside the policy: the exoskeleton actor acts first and the human actor receives its command of the same step ([1], p. 4). The environment observation keeps the same width at every stage.

**D-OBS-05. Observation width.** For Stages 2-4 the environment observation has 83 dimensions (65 + 18). MyoAssist sizes the observation space by calling `step()` once, which already includes the exoskeleton block; the block is counted once.

**D-ACT-01. Action space.** One 28-dimensional action space (26 muscles + 2 device actuators) is used at every stage. At Stage 1 the policy samples the 26 muscle actions and sets the two device actions to zero; the device actuators are inert.

## 5. Reward

The outer weights per stage follow Table S2 and the per-joint imitation weights follow Table S3 (`stage_config.py`). The SMAT-specific terms (hip-activation reward, exoskeleton reward, torque-change reward) follow the equations of [1] (`reward_terms.py`) and are added on top of MyoAssist's native reward terms.

**D-RWD-01. Weighting of the imitation terms.** MyoAssist applies the per-joint imitation weights inside the position and velocity imitation terms and then weights each term again by the sum of its per-joint weights. This behaviour is kept, since SMAT was built on the same code.

**D-RWD-02. Lumbar joint.** The 26-muscle model has no lumbar joint (the torso is welded to the pelvis); lumbar keys used by MyoAssist's 2D tutorial configuration are omitted.

**D-RWD-03. End-effector imitation.** MyoAssist's end-effector imitation term is a stub that always returns zero. Its weight is zero at every stage, and neither SMAT paper uses such a term.

**D-RWD-05. Tracked joints.** MyoAssist's out-of-trajectory check uses exactly the joints with a nonzero position-imitation weight. From Stage 3 on, Table S3 sets the hip weights to zero, so the hips are neither rewarded for imitation nor checked for deviation in Stages 3 and 4.

**D-REW-UPSTREAM-01. Later MyoAssist changes.** Upstream commit `54e9fee` (2026-08-18) squares the muscle-activation penalty, adds a device-effort penalty and removes the device state from the observation. None of these changes is applied: SMAT used the linear penalty.

## 6. Termination

**D-TERM-01. Termination causes.** MyoAssist reports termination and truncation only as booleans. Each episode end is labelled with one cause, checked in this order: reference end, fall, out-of-trajectory, time limit. The labels are used for logging and evaluation only; termination behaviour is unchanged.

**D-TERM-02. Termination rule.** Neither paper reports a termination rule, and Algorithm S1 contains none. With MyoAssist's tutorial threshold of 0.2 rad, episodes of an untrained policy end within a few control steps. An episode ends when:

- any tracked joint deviates from the reference by more than 0.6 rad (variant T06, primary) or 0.2 rad (variant T02, alternative);
- the pelvis drops below 0.7 m;
- the reference trial ends; or
- 1000 control steps (20 s) have elapsed.

## 7. Target speed

**D-VEL-01. Fixed target speed.** MyoAssist's per-episode target-speed randomiser (`_change_mode_and_target_velocity_randomly`) passes its six positional arguments shifted by one slot. Its bounds are therefore corrupted at every training reset, even when the minimum and maximum are equal: four successive resets drove a configured 1.2 m/s target to 4.64, 6.02, 6.07 and 3.88 m/s. The method is replaced by a keyword call of the same, unmodified, MyoAssist setter.

The target speed is fixed at the mean forward speed of the reference trial, v* = 1.2818 m/s, at every stage. The papers state 1.25 m/s.

## 8. Policies and stage transitions

**D-POLICY-01. Policy implementation.** The two-actor, shared-critic policy is implemented directly (`policy.py`) rather than through MyoAssist's network-index mechanism:

- human actor: MLP 256-128 with 26 outputs ([1], p. 2);
- exoskeleton actor: MLP 128-64 with 2 outputs, on the 18-dim exoskeleton observation ([1], p. 2);
- one shared critic over the full state;
- Gaussian actions with a learned, state-independent log standard deviation;
- orthogonal initialisation and Adam over the trainable parameters only.

**D-POLICY-02. Frozen human actor.** In Stage 3 the frozen human actor still samples its actions; only its parameter updates are disabled. This follows Algorithm S1, which rolls out both actors and updates only the exoskeleton actor and the critic.

**D-POLICY-03. Stage transitions.** `transfer_weights()` copies every tensor whose shape matches.

- 1 → 2: the human actor, critic and log standard deviation are copied, and the exoskeleton actor starts from its initialisation.
- 2 → 3: the Stage-2 exoskeleton actor is discarded and re-initialised, as [1] describes.
- 3 → 4: the human actor's input grows by the two command dimensions. Its existing weights are copied, and the new input columns are drawn from N(0, 0.01), following [1] ("randomly initialized", p. 4).

A transfer is applied only when a stage starts; a resumed stage reloads its own checkpoint.

**D-POLICY-04. Stage 2 updates.** Stage 2 updates the human actor and the critic only, as in Algorithm S1. The exoskeleton actor is not trained while its torque is zero, so its action probabilities do not enter the PPO ratio.

## 9. PPO

**D-PPO-01. Hyperparameters.** All eleven rows of Table S4 are used:

- learning rate 5e-5 (Stage 1), 3e-5 (Stages 2-4);
- clip range 0.15;
- 2048 rollout steps per environment;
- minibatch 16,384;
- 20 epochs;
- discount 0.99;
- GAE λ 0.95;
- target KL 0.01;
- maximum gradient norm 0.5;
- entropy coefficient 0.001 (Stages 1-2), 0.003 (Stages 3-4);
- 32 parallel environments.

Table S4 has no value-loss coefficient; the Stable-Baselines3 default, 0.5, is used at every stage.

## 10. Parallel environments and throughput

**D-VEC-01. Vectorised environments.** Stable-Baselines3's `SubprocVecEnv` with the spawn start method, one environment per worker process; environment i uses seed + i. Environment parameters are passed as live dataclass instances: rebuilding them from a dictionary through MyoAssist's `DictionableDataclass.create()` would drop the three SMAT-specific reward fields.

**D-PERF-01. Worker placement.** On a 128-thread AMD Threadripper PRO 5995WX, a 32-worker step took 19.2 ms although a single environment steps in 3.5 ms. Idle workers migrated between CPU chiplets, which doubled their in-step CPU time to 6.9 ms. With one worker pinned per CPU (`SMAT_PIN_WORKERS=1`, set by `deploy/launch_stage.sh`) the step takes 9.0 ms. The launcher also sets single-threaded math libraries in the workers and four threads in the PPO process. These settings change process placement only; environments, seeds and hyperparameters are unchanged. Measured throughput is about 1,300 environment steps per second per 32-environment run on Zen 3 CPUs.

## 11. Control conditions

**D-CTRL-01. Stage-4 controls.** Both controls are options of `train.py` and start from the same Stage-3 policy as condition (d):

- (b) `--tau-max-override 0.0`: the device is worn and commanded but applies no torque, and the exoskeleton reward terms are still computed on the command;
- (f) `--tau-max-override 0.0 --zero-exo-reward`: additionally removes the exoskeleton reward r_exo and the torque-change reward r_Δτ from the summed reward.

The hip-activation reward is kept in both. Device-off evaluation of condition (d) is an evaluation-time option (`evaluate_gait_gate.py --device-off`).

## 12. Evaluation

**D-EVAL-01. Joint-limit contact.** A hip counts as at its limit when MuJoCo's joint-limit constraint for that joint carries non-zero force. If the constraint rows cannot be read, a position-proximity test (within 0.001 rad of the range bound) is used instead; the method used is reported.

**D-EVAL-02. Range of motion.** Hip and knee ranges of motion, and their symmetry index SI = |X_r − X_l| / (0.5 (X_r + X_l)) × 100 %, are computed per episode (maximum minus minimum), not per detected stride.

**D-EVAL-03. One checkpoint per call.** The evaluation tool scores one checkpoint per call over 10 deterministic episodes (seeds 0-9). Comparisons between stages and conditions are made across the resulting JSON files.

**Gait criteria.** Computed from the evaluation JSON:

| | Criterion |
|---|---|
| G1 | mean hip range of motion ≥ 30° on each leg |
| G2 | mean knee range of motion ≥ 40° on each leg |
| G3 | each hip at its limit in < 5 % of steps |
| G4 | mean episode length ≥ 500 steps, and at most 5 of 10 episodes ending by deviation within their first 100 steps |
| G5 | mean forward speed within 15 % of v* |
| G6 | symmetry index < 20 % for hip and knee range of motion |

All six apply at the end of Stages 1, 2 and 4; G1, G2 and G4 apply at Stage 3. G1-G3 are also checked at the first Stage-1 checkpoint at or after 20M steps.

**Activation metric.** For each condition X, comparator C and seed s, the percentage reduction is the mean over the four right-side hip muscles (iliopsoas, gluteus maximus, rectus femoris, hamstrings) of 100 × (1 − A_X / A_C). Here A is the time-weighted mean activation of that muscle over all evaluated steps.
